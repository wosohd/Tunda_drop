# TundaDrop Payment Testing Log

## Purpose

This file records the payment integration tests completed for TundaDrop during the M-Pesa and Stripe checkout debugging session.

The goal was to confirm that customers can move from cart to checkout, select a payment method, and complete or initiate payment correctly.

---

## Payment Systems Tested

TundaDrop currently supports two checkout payment paths:

1. M-Pesa
2. Stripe card payment

---

```env
EXPO_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
```

```env

```

## Stripe PaymentIntent Endpoint Test

### Command

```powershell
$body = @{
  amount = 150000
  currency = "kes"
  orderReference = "TD-TEST-001"
  customer = @{
    name = "Test Customer"
    email = "test@tundadrop.com"
    phone = "0712345678"
    address = "Nairobi CBD"
  }
} | ConvertTo-Json -Depth 3

Invoke-RestMethod `
  -Uri "http://localhost:3000/stripe/create-payment-intent" `
  -Method POST `
  -ContentType "application/json" `
  -Body $body
```

### Expected Result

```txt
success         : True
clientSecret    : pi_..._secret_...
paymentIntentId : pi_...
```

### Issues Encountered

Initial error:

```txt
Invalid API Key provided
```

### Root Cause

The backend was using an invalid Stripe key or the wrong kind of Stripe credential.

### Fix

The backend `.env` was updated to use the real Stripe Secret Key from:

```txt
Stripe Dashboard -> Developers -> API keys -> Secret key
```

The backend was then restarted.

### Final Status

Passed.

The backend successfully created a Stripe PaymentIntent.

## Expo App Startup Test

### Command

```powershell
npx expo start --clear
```

### Issues Encountered

#### Issue 1: Expo Bundling Backend Files

Error indicated that Expo was trying to bundle backend files:

```txt
Unable to resolve "@babel/runtime/helpers/asyncToGenerator" from "routes/stripe.js"
```

### Root Cause

Backend files were visible to the Expo mobile app bundler or placed outside the proper backend folder.

### Fix

Backend files were kept inside:

```txt
backend/server.js
backend/routes/stripe.js
backend/package.json
backend/.env
```

The mobile app only imports:

```txt
src/lib/stripeService.js
```

It does not import backend files directly.

---

#### Issue 2: Stripe Plugin Config Error

Error:

```txt
Cannot read properties of undefined (reading 'merchantIdentifier')
```

### Root Cause

The Stripe config plugin in `app.json` was included without an options object.

### Fix

Updated `app.json` plugin entry:

```json
[
  "@stripe/stripe-react-native",
  {
    "merchantIdentifier": "",
    "enableGooglePay": false
  }
]
```

Also removed `merchantIdentifier` from the runtime `StripeProvider` in `_layout.js`.

### Final Status

Passed.

Expo started successfully.

## Checkout Navigation Test

### Issue Encountered

Phone displayed:

```txt
Unmatched route page cannot be found
```

### Root Cause

The app was navigating to an incorrect checkout route.

The correct checkout file is:

```txt
app/(shop)/checkout.js
```

Because `(shop)` is an Expo Router route group, the real path is:

```txt
/checkout
```

### Fix

Cart checkout navigation should use:

```js
router.push("/checkout");
```

### Final Status

Passed.

The app successfully navigated to checkout.

3. Select quantity.
4. Add item to cart.
5. Proceed to checkout.
6. Enter delivery details.
7. Select M-Pesa.

The app reached the M-Pesa payment initiation step, but the M-Pesa prompt did not appear.

Error shown:

```txt
M-Pesa start fail, Edge Function returned a non-2xx status code
```

### Interpretation

The mobile checkout flow is working correctly.

The remaining issue is inside the Supabase Edge Function or M-Pesa Daraja environment configuration.

1. Supabase Edge Function secrets.
2. M-Pesa consumer key and consumer secret.
3. M-Pesa shortcode.
4. M-Pesa passkey.
5. Callback URL.
6. Phone number format.
7. Daraja sandbox/live environment mismatch.
8. Edge Function logs.
9. Daraja API response body.

### Final Status

Partially passed.

App flow passed. STK Push backend initiation needs further debugging.
